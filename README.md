# Арена переговоров

[Открыть тренажёр](https://chernozemual.github.io/negotiation-arena/) · [Исходный код](https://github.com/chernozemUal/negotiation-arena) · [Презентация](https://chernozemual.github.io/negotiation-arena/presentation/)

Работающий учебный MVP по ТЗ «ОЭЗ ППТ Алабуга». Короткие переговоры с безопасной повторной попыткой и разбором конкретных решений.

## Запуск

Нужны Node.js 22+ и npm. Проверяемый браузер: Chromium/Chrome.

```bash
npm ci
npm run build
npm start
```

Открыть http://localhost:3000. Для разработки: `npm run dev`. Установка требует интернет; приложение после запуска не обращается к внешним API. Для сценарного режима ключи и переменные окружения не нужны. Зависимости зафиксированы в package-lock.json.

## Продукт и путь пользователя

Аудитория: начинающие руководители, закупщики, сотрудники, готовящиеся к карьерному разговору. Проблема: знание теории не даёт безопасной регулярной практики. Ценность: короткий повторяемый диалог, видимые последствия выбора и обратная связь на собственные реплики.

Путь: приветственная легенда из четырёх глав → выбор сценария → брифинг с целями и альтернативой → контакт → выяснение интересов → предложение → фиксация → разбор → повтор. Два полноценных сценария: повышение цены поставщиком и карьерное повышение. Каждая стадия содержит три тактики; реакции меняются по действиям и доверию. Финалы: достигнутая договорённость, отсутствие договорённости, досрочное завершение.

## Демонстрация для жюри (3–5 минут)

1. В конструкторе выбрать сферу, тему, сложность, тон, роль и цель. Сохранить. Нажать «Протестировать».
2. В первом прогоне выбрать конструктивные ответы на четырёх этапах; открыть разбор.
3. Повторить с угрозами и уступками: сравнить доверие, очки и исход.
4. Показать прогресс и перезагрузить страницу: результаты сохранятся.
5. Презентация доступна по `/presentation`, готовый PDF — `public/arena-presentation.pdf`; её можно показать в браузере или сохранить в PDF через печать. Для сдачи разместить репозиторий и приложить ссылки на документацию и презентацию.

## Архитектура и методы

Next.js App Router + TypeScript; Tailwind CSS и собственные CSS-компоненты; Lucide React; Framer Motion; Zustand persist. `lib/engine.ts` — чистая логика сценариев, оценки и реакций. `lib/store.ts` — контекст, состояние сессии и история. `app/page.tsx` — тренажёр, конструктор, прогресс и разбор. Серверной БД нет: localStorage хранит настройки, активную сессию и последние 50 результатов в этом браузере. Очистка данных браузера удалит прогресс. XP и уровень рассчитываются по сохранённой истории.

Сфера подбирает один из двух сюжетов, сложность меняет необходимый результат (52/65/78 из 100), тон меняет стиль ответа, цель включается в обсуждение интересов; роль и тема отображаются в контексте. Произвольные темы не генерируют новые сюжеты: для этого нужен будущий редактор сценариев. Доверие стартует с 50%, действия изменяют его, при падении ниже 25% собеседник предупреждает об остановке. Для успеха нужны все 4 этапа, порог очков и доверие минимум 40%. Время измеряется без принудительного лимита.

Напряжённость — отдельный показатель от 5 до 100%. На старте дружелюбный, сдержанный и жёсткий тон задают 24, 36 и 48%; продвинутый уровень добавляет 5 пунктов, экспертный — 10. Давление повышает напряжение, конструктивные действия снижают его. Уступка без обсуждения может одновременно немного повысить доверие и увеличить напряжение: интересы ещё не согласованы. На 45% появляется осторожный диалог, на 70% — состояние на грани срыва. Показатель вычисляется по настройкам сессии и истории ходов, поэтому восстанавливается после перезагрузки; сам по себе он не меняет критерии победы.

В настройках доступны спокойный режим с отключением фонового движения и пульсации, повтор приветственной легенды и ссылка на получение API-ключа OpenAI. Это внешняя ссылка: поле ввода ключа и подключение нейросети не реализованы, ответы по-прежнему формирует сценарный движок.

Свободный текст оценивается прозрачной эвристикой по ключевым признакам текущего этапа и давления. Это не LLM, не семантическая оценка и не валидированный психометрический тест. Разбор предлагает учебные рекомендации. Уровни и XP мотивируют повторять практику, но не подтверждают профессиональную квалификацию.

## Границы MVP

Нет регистрации, ролевой авторизации, синхронизации устройств, голосового режима и внешних AI-сервисов. Конструктор — открытый демонстрационный интерфейс администратора. Нельзя использовать как закрытый корпоративный кабинет без добавления серверной авторизации. Данные не покидают браузер. Настройки новой сессии не меняют уже начатую. Запуск новой практики заменяет незавершённую сессию (об этом сообщает брифинг).

## Проверки

```bash
npm test
npm run typecheck
npm run build
```

Тесты проверяют успешные/неуспешные пути обоих сценариев, невозможность успеха незавершённой сессии, влияние настроек на реакции, пороги и обработку свободных реплик. Проверки напряжённости охватывают влияние тона и сложности, рост при давлении, снижение при конструктиве, границы на всех четырёхэтапных ветках, отличие от доверия и восстановление из сохранённых ходов.

## Библиотеки и доступ

Все библиотеки устанавливаются из npm; ключи не нужны. Документация: [Next.js](https://nextjs.org/docs), [React](https://react.dev), [Tailwind CSS](https://tailwindcss.com), [Zustand](https://zustand.docs.pmnd.rs), [Motion](https://motion.dev), [Lucide](https://lucide.dev). Внешние сервисы не используются; визуальная сцена создана CSS. Методическая структура — контакт, интересы, взаимовыгодное предложение, письменная фиксация; сценарии и шкала авторские, требуют последующей проверки экспертами.

## Результаты проверки реализации

Проверены production-сборка, TypeScript и 12 тестов движка. Браузерный скрипт покрывает легенду, напряжённость, исходы обоих сценариев, настройки и сохранение состояния. Проверка адаптивности выполняется на размерах 1440×900, 1366×768, 390×844, 375×667 и 320×568. Скрипт браузерной проверки: `docs/browser-smoke.py` (Python 3, Chromium, ChromeDriver на порту 9515 и запущенный сервер на порту 3000). После обновления PostCSS npm audit не сообщает известных уязвимостей на момент проверки.

## Обновлённый интерфейс

Меню и основные кнопки занимают один экран. История реплик, длинная история сессий, формы на небольших дисплеях и подробный разбор прокручиваются внутри своих панелей; страница целиком не прокручивается. Разбор разбит на переключаемые этапы. Шрифт полей ввода на мобильных устройствах — 16 px для удобного ввода без автоматического увеличения страницы.

Первое знакомство состоит из четырёх глав: легенда, навигация, реплики и напряжённость, результаты и настройки. Его можно пропустить или повторить из настроек. Завершение знакомства и спокойный режим сохраняются локально. Анимации учитывают `prefers-reduced-motion`; плавные переходы экранов и сообщений дополняются медленной подсветкой при высоком напряжении. Звука, вспышек и тряски нет.

Черновик свободной реплики сохраняется вместе с текущей сессией, включая переходы между экранами и перезагрузку. Повтор из истории сначала открывает брифинг: при активной сессии видимо предупреждение о её замене.

## Публичная тестовая версия

Хостинг — GitHub Pages из ветки `gh-pages`. Исходники находятся в `main`; в `gh-pages` попадает только статическая сборка и `.nojekyll`. Для обновления сайта: `npm run deploy` (нужны Git и авторизованный GitHub CLI). Скрипт запускает тесты, собирает сайт и публикует артефакты без принудительной перезаписи истории. Публичная версия работает без сервера и API-ключей. Каждый тестировщик получает собственный локальный прогресс в своём браузере; общей базы результатов нет.

Для публикации используется `STATIC_EXPORT=true`, а `NEXT_PUBLIC_BASE_PATH` указывает на имя репозитория. Внутренние ссылки используют Next.js Link и учитывают путь репозитория. В обычном локальном запуске эти переменные не нужны.

Сообщить об ошибке можно через [GitHub Issues](https://github.com/chernozemUal/negotiation-arena/issues). Укажите устройство, размер экрана, сценарий, шаги и ожидаемый результат.

Необязательный шаблон автоматического деплоя через Actions сохранён в `docs/deploy-pages.workflow.yml`. Для его активации потребуется право `workflow`; текущая публикация этого права не требует.
