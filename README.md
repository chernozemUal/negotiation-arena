# Арена переговоров

[Открыть тренажёр](https://chernozemual.github.io/negotiation-arena/) · [Исходный код](https://github.com/chernozemUal/negotiation-arena) · [Презентация](https://chernozemual.github.io/negotiation-arena/presentation/)

Работающий учебный MVP по ТЗ «ОЭЗ ППТ Алабуга». Полноценные шестишаговые переговоры с безопасной повторной попыткой, голосовым режимом и разбором конкретных решений.

## Запуск

Нужны Node.js 22+ и npm. Проверяемый браузер: Chromium/Chrome.

```bash
npm ci
npm run build
npm start
```

Открыть http://localhost:3000. Для разработки: `npm run dev`. Установка требует интернет. Для сценарного режима ключи и переменные окружения не нужны. При подключении пользователем собственного ключа браузер обращается напрямую к OpenAI. Зависимости зафиксированы в package-lock.json.

## Продукт и путь пользователя

Аудитория: начинающие руководители, закупщики, сотрудники, готовящиеся к карьерному разговору. Проблема: знание теории не даёт безопасной регулярной практики. Ценность: короткий повторяемый диалог, видимые последствия выбора и обратная связь на собственные реплики.

Путь: приветственная легенда → выбор сценария → брифинг с целями и альтернативой → контакт → сверка позиций → интересы → пакет условий → работа с возражением → фиксация → разбор → повтор. Два полноценных сценария: повышение цены поставщиком и карьерное повышение. Каждый из шести этапов содержит три тактики, свободный текст и голосовой ввод; реакции меняются по действиям, доверию и контексту. Финалы: достигнутая договорённость, отсутствие договорённости, досрочное завершение.

## Демонстрация для жюри (3–5 минут)

1. В конструкторе выбрать сферу, тему, сложность, тон, роль и цель. Сохранить. Нажать «Протестировать».
2. В первом прогоне выбрать конструктивные ответы на шести этапах; открыть разбор.
3. Повторить с угрозами и уступками: сравнить доверие, очки и исход.
4. Показать прогресс и перезагрузить страницу: результаты сохранятся.
5. Презентация доступна по `/presentation`, готовый PDF — `public/arena-presentation.pdf`; её можно показать в браузере или сохранить в PDF через печать. Для сдачи разместить репозиторий и приложить ссылки на документацию и презентацию.

## Архитектура и методы

Next.js App Router + TypeScript; Tailwind CSS и собственные CSS-компоненты; Lucide React; Framer Motion; Zustand persist. `lib/engine.ts` — чистая логика сценариев, оценки и реакций. `lib/store.ts` — контекст, состояние сессии и история. `app/page.tsx` — тренажёр, конструктор, прогресс и разбор. Серверной БД нет: localStorage хранит настройки, активную сессию и последние 50 результатов в этом браузере. Очистка данных браузера удалит прогресс. XP и уровень рассчитываются по сохранённой истории.

Сфера подбирает один из двух сюжетов, сложность меняет необходимый результат (52/65/78 из 100), тон меняет стиль ответа, цель включается в обсуждение интересов; роль и тема отображаются в контексте. Произвольные темы не генерируют новые сюжеты: для этого нужен будущий редактор сценариев. Доверие стартует с 50%, действия изменяют его, при падении ниже 25% собеседник предупреждает об остановке. Для успеха нужны все 6 этапов, порог баллов и доверие минимум 40%. Баллы нормализуются до шкалы 0–100. Время измеряется без принудительного лимита.

Напряжённость — отдельный показатель от 5 до 100%. На старте дружелюбный, сдержанный и жёсткий тон задают 24, 36 и 48%; продвинутый уровень добавляет 5 пунктов, экспертный — 10. Давление повышает напряжение, конструктивные действия снижают его. Уступка без обсуждения может одновременно немного повысить доверие и увеличить напряжение: интересы ещё не согласованы. На 45% появляется осторожный диалог, на 70% — состояние на грани срыва. Показатель вычисляется по настройкам сессии и истории ходов, поэтому восстанавливается после перезагрузки; сам по себе он не меняет критерии победы.

В настройках доступны спокойный режим, повтор приветственной легенды и BYOK-подключение OpenAI. Пользователь вставляет свой API-ключ, выбирает модель и запускает проверку доступа. По умолчанию ключ хранится в `sessionStorage` до закрытия вкладки; постоянное сохранение в `localStorage` включается отдельным флажком. Ключ не попадает в исходный код, GitHub или базу приложения. После подключения OpenAI генерирует реплики собеседника, а локальный движок продолжает считать очки, доверие и напряжённость. При ошибке API сессия автоматически использует сценарный ответ.

Клиентское хранение ключа менее безопасно, чем серверная интеграция: любой JavaScript, исполняющийся на странице, потенциально имеет к нему доступ. Этот режим добавлен для личного тестирования на статическом GitHub Pages по модели «свой ключ». Для общего корпоративного использования следует перенести вызов OpenAI на сервер и хранить ключ в секретах хостинга. Запросы могут тарифицироваться в аккаунте владельца ключа. Для генерации используется Responses API с `store: false`; проверка подключения запрашивает метаданные выбранной модели без генерации текста.

Свободный текст оценивается прозрачной эвристикой по ключевым признакам текущего этапа и давления. Это не LLM, не семантическая оценка и не валидированный психометрический тест. Разбор предлагает учебные рекомендации. Уровни и XP мотивируют повторять практику, но не подтверждают профессиональную квалификацию.

## Границы MVP

Нет регистрации, ролевой авторизации и синхронизации устройств. Конструктор — открытый демонстрационный интерфейс администратора. Нельзя использовать как закрытый корпоративный кабинет без добавления серверной авторизации. При включённом OpenAI текст диалога отправляется в API для генерации ответа. Голосовой ввод использует браузерный Web Speech API и требует разрешения на микрофон; в Chrome распознавание может выполняться внешним онлайн-сервисом браузера и не работать офлайн. Проверяемый браузер — актуальный Chrome. Озвучивание выполняется системным голосом устройства. Настройки новой сессии не меняют уже начатую. Запуск новой практики заменяет незавершённую сессию (об этом сообщает брифинг).

## Проверки

```bash
npm test
npm run typecheck
npm run build
```

Тесты проверяют успешные/неуспешные пути обоих шестишаговых сценариев, невозможность успеха незавершённой сессии, нормализацию баллов, влияние настроек на реакции, пороги и обработку свободных реплик. Проверки напряжённости охватывают влияние тона и сложности, рост при давлении, снижение при конструктиве, границы на всех ветках, отличие от доверия и восстановление из сохранённых ходов.

## Библиотеки и доступ

Все библиотеки устанавливаются из npm. Документация: [Next.js](https://nextjs.org/docs), [React](https://react.dev), [Tailwind CSS](https://tailwindcss.com), [Zustand](https://zustand.docs.pmnd.rs), [Motion](https://motion.dev), [Lucide](https://lucide.dev), [Web Speech API](https://developer.mozilla.org/docs/Web/API/Web_Speech_API), [Web Audio API](https://developer.mozilla.org/docs/Web/API/Web_Audio_API), [OpenAI Responses API](https://developers.openai.com/api/docs/quickstart). Методическая структура — контакт, позиции, интересы, взаимовыгодный пакет, работа с возражением и письменная фиксация; сценарии и шкала авторские, требуют последующей проверки экспертами.

## Результаты проверки реализации

Проверены production-сборка, TypeScript, 12 тестов движка и 5 тестов OpenAI-интеграции. Браузерный скрипт полностью проходит оба шестишаговых сценария и проверяет легенду, увеличенные размеры текста, напряжённость, тёмную тему, голосовые элементы, настройки и восстановление состояния. Отдельная браузерная проверка покрывает подключение, хранение и удаление ключа, AI-реплику и возврат к сценарию при ошибке API. Адаптивность проверяется на размерах 1440×900, 1366×768, 390×844, 375×667 и 320×568 без прокрутки всей страницы и скрытых основных элементов. Скрипт: `docs/browser-smoke.py` (Python 3, Chromium, ChromeDriver и запущенный сервер на порту 3000). После обновления PostCSS npm audit не сообщает известных уязвимостей на момент проверки.

## Обновлённый интерфейс

Меню и основные кнопки занимают один экран. История реплик, длинная история сессий, формы на небольших дисплеях и подробный разбор прокручиваются внутри своих панелей; страница целиком не прокручивается. Разбор разбит на переключаемые этапы. Шрифт полей ввода на мобильных устройствах — 16 px для удобного ввода без автоматического увеличения страницы.

Первое знакомство состоит из четырёх глав: легенда, навигация, реплики и напряжённость, результаты и настройки. Его можно пропустить или повторить из настроек. Тема, звуковые эффекты, автоозвучивание и спокойный режим сохраняются локально. Светлая и тёмная палитры используют увеличенную типографику и контрастные состояния. Анимации учитывают `prefers-reduced-motion`; звуковые эффекты короткие и отключаются отдельно. Каждую реплику соперника можно озвучить повторно кнопкой на сообщении.

Черновик свободной реплики сохраняется вместе с текущей сессией, включая переходы между экранами и перезагрузку. Повтор из истории сначала открывает брифинг: при активной сессии видимо предупреждение о её замене.

## Сверка с техническим заданием

- **Продукт и концепция:** указаны аудитория, проблема, ценность относительно лекций и ролевых тренингов, полный путь от входа до повторной попытки.
- **Сценарии и влияние стратегии:** реализованы два шестишаговых сценария с конструктивными, нейтральными и конфликтными ветками; формулировки меняют баллы, доверие, напряжённость, ответ и финал.
- **Конфигурируемость:** конструктор задаёт сферу, тему, сложность, тон, роль и цель; настройки участвуют в брифинге, пороге успеха, стартовом напряжении и ответах.
- **Контуры пользователя и администратора:** практика, прогресс и разбор отделены от конструктора контекста.
- **Геймификация и UX/UI:** уровень, XP, прогресс, состояние собеседника, светлая/тёмная темы, адаптивная навигация, звук, озвучивание и голосовой ввод.
- **Воспроизводимость:** публичный деплой, открытый код, зафиксированные зависимости и запуск тремя командами. Платный API необязателен: оба сценария полностью проходят автономно.
- **Материалы финальной сдачи:** README служит сопроводительной документацией, `/presentation` и `public/arena-presentation.pdf` содержат презентацию, ссылки на прототип и репозиторий размещены в начале файла.

Границы относительно будущего корпоративного продукта: произвольная тема пока уточняет один из двух подготовленных сюжетов, интерфейс администратора не защищён авторизацией, результаты не синхронизируются между устройствами, а учебная эвристика требует проверки тренерами.

## Публичная тестовая версия

Хостинг — GitHub Pages из ветки `gh-pages`. Исходники находятся в `main`; в `gh-pages` попадает только статическая сборка и `.nojekyll`. Для обновления сайта: `npm run deploy` (нужны Git и авторизованный GitHub CLI). Скрипт запускает тесты, собирает сайт и публикует артефакты без принудительной перезаписи истории. Публичная версия работает без сервера; OpenAI включается ключом конкретного тестировщика. Каждый тестировщик получает собственные настройки и прогресс в своём браузере; общей базы результатов нет.

Для публикации используется `STATIC_EXPORT=true`, а `NEXT_PUBLIC_BASE_PATH` указывает на имя репозитория. Внутренние ссылки используют Next.js Link и учитывают путь репозитория. В обычном локальном запуске эти переменные не нужны.

Сообщить об ошибке можно через [GitHub Issues](https://github.com/chernozemUal/negotiation-arena/issues). Укажите устройство, размер экрана, сценарий, шаги и ожидаемый результат.

Необязательный шаблон автоматического деплоя через Actions сохранён в `docs/deploy-pages.workflow.yml`. Для его активации потребуется право `workflow`; текущая публикация этого права не требует.
